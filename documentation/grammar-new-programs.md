# New grammar programs as data (#62f; #62g/#62h append here)

How a grammar program is added without new lesson code, and why each piece is the way it is.
First used for «Прилагательные» (#62f, plan `plans/improvements/active/plan_62f_grammar-adjectives.md`).

## The data-only approach

The Numbers program was the precedent: a program is (1) case indices with a group name in
`backend/data/grammar/lessons.json` `cases`, (2) a basic/advanced/practice lesson triple per case in
`lessons`, (3) a `GrammarCaseRule` + `GrammarSentence` rows per case, (4) a `GrammarProgram` row whose
`lesson_filter` is `["<group>"]`. The existing noun pipeline (`grammar_service._generate_sentence_tasks`,
`filterLessonsForProgram`, `_program_lesson_ids`, the knowledge check) then does everything.

#62f: case indices 21–26, group `Būdvardžiai`, lessons 106/112/118/124/130/136 (+1 advanced, +2 practice).

## Constraints

- **Lesson ids stay below 200.** `remind_tasks` and the frontend's `filterLessonsForProgram` treat
  `id >= 200` as a verb lesson. Next free basic ids follow the step-6 pattern after 136: 142, 148, …
- **Never add the program to `_SEED_PROGRAMS`** (`routers/grammar.py`). `_ensure_seed` creates
  missing seeds on the first request — public, in prod, with `lesson_filter` NULL (= every noun
  lesson). The generic seed creates it hidden instead.
- **A program with `lesson_filter` NULL shows every noun lesson** — including new groups once their
  rules are published. Prod «Литовские падежи» has `["Vienaskaita","Daugiskaita"]`, so it does not
  pick up adjectives; a local DB with NULL would.

## Why `adjectives.txt` is separate from `paradigms_extra.txt`

`paradigms_extra.txt` lines are an unordered bag of forms (order "irrelevant"), so there is no
dictionary form to show in the «от: …» hint. `adjectives.txt` has the dictionary form in column 1
(`_ADJ_FORM_TO_FORMS` → `_sentence_base_lt`). It is checked **last** in `_paradigm_forms`, after the
noun and numeral tables, and the validator rejects any adjective form that also occurs in
`words.txt` / `paradigms_extra.txt`, so a noun row's options and hint can never change.
The file is generated by `scripts/build_adjective_paradigms.py` from a rule table per declension
type (`-as/-a`, `-ias/-ia`, `-us/-i` with t→č / d→dž before i + vowel, `-is/-ė`); edit the script.

## The generic seed (`scripts/seed_grammar_program.py`)

- One script, one validator per `"format"` (an if/elif, like `seed_practice_category.py`); pytest
  imports the validator from the script.
- **Idempotent:** rules are inserted only for case indices without one; sentences only for case
  indices that have **none** yet (a partial rerun never duplicates rows). Later fixes go through the
  admin grammar editor — there is no `--reset`.
- **The program is upserted by title, never deleted:** `UserGrammarProgram` rows reference it.
  An existing program keeps its `is_public` — releasing is an admin step.
- Rules land `testing`, the program `is_public = false`. Writes come from the script's own process:
  the app cache shows them within its 10-minute TTL or after a restart (`documentation/caching.md`).
- Every sentence carries `"source": "tatoeba:<id>" | "commonvoice" | "own"` (the seed ignores it,
  the validator requires it). `tatoeba:<id>` is kept for adapted sentences too (attribution).

## Release order

Make the program public **and** publish its case rules in one admin pass. Published rules with a
hidden program put the lessons into knowledge checks and the continue session with no program to
recommend; a public program with unpublished rules shows no lessons. Rollback = both back.
Admins can preview a hidden program before that: `GET /grammar-programs` returns hidden programs
(with `is_public`) to admins and admins may enroll in them (#62f).

## Why the duplicate-word cleanup was removed

`_generate_sentence_tasks` used to delete `full_word` from the text after the blank when it appeared
there as a substring. No prod row triggered it (checked 2026-10-08), but adjective rows would
(«Tai ger___ knyga, o filmas geras.» → «…filmas s.»), and so would #62g's prefix rows. Display is
now served as stored.

## Limit: diacritics at the typing levels

Typed answers go through `normalizeLt`, which drops diacritics, so at Advanced/Practice «gera» and
«gerą» are both accepted. The nominative/accusative (and -os/-ų style) contrast is only really
tested at Basic, where the 4 options are compared with diacritics kept.

## Endings line on the rule card

The rule card prints endings as one line (approved in the #62f prototype). The seed data uses the
non-breaking hyphen U+2011 in `endings_*` so «‑ios» never wraps after its hyphen at 375px.
