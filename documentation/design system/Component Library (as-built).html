FLUENT.LT

Component library — as-built

What's actually implemented in frontend/ after the TAK mascot redesign, kept in sync with the code. This page is the visual source of truth going forward — the original design mockups that the redesign was built from have been retired now that the redesign shipped, including the places implementation deliberately diverged (mobile sizing, a11y, existing i18n/data constraints).

Per CLAUDE.md: update this file whenever a new shared component or pattern is introduced. This is the source of truth for visual/component decisions during development — check it before inventing a new pattern.

Principles

  1. This page is the visual source of truth. It defines layout, spacing and colour for what shipped. Any new pattern should match what's documented here, or be added here alongside the "Deliberate deviations" table below.
  2. Flat, not decorated. Cards are white with a 1px #ececec border and no drop shadow. Buttons carry no shadow or glow. No decorative blur blobs, no gradient fills on components — the only gradient in the product is the page wash on body.
  3. Tokens, not raw palette steps. Use the named colours above. Never reach for a stock Tailwind step (gray-100, emerald-500) when a token exists — that drift is what caused inconsistency in the app before.
  4. One typeface. Inter everywhere. The original mockups used no second display face, so font-headline (Manrope) is not applied on redesigned pages.
  5. Green is words, purple is phrases. #0f9d68 is the words/global accent; #9333ea is the phrases surface. Correct/incorrect feedback stays green/red regardless of surface — that is semantic, not brand.
  6. Hover goes darker, never lighter. emerald-600 → emerald-700.
  7. Layout: full-bleed navbar, 1180px content. The header spans the viewport; page content sits in .page (max 1180px, 32px gutters, 16px below 860px).
  8. Breakpoints: not Tailwind defaults — 3→2 columns at 1200px, →1 column at 860px (see "Deliberate deviations" for why 1200px, not the originally planned 1000px).
  9. Readability outranks fidelity. If a documented value is genuinely hard to read, darken it and record it as a deliberate deviation. Small-caps secondary labels use #5b6067.
  10. TAK is the only mascot, and replaces decorative emoji plus decorative navigational arrows — never small functional glyphs (dropdown/accordion carets, the ⭐ difficulty rating). See Emoji policy.
  11. One mascot per screen, at 128px, via PageMascot. Every page outside /dashboard/admin/** shows exactly one, and his emotion tracks the session mood. The two bare icon call sites (bug-report FAB, landing streak ring) and the navbar's TakMark logo icon are the only exemptions.

TAK — the mascot

frontend/components/Tak.tsx. One polygon (torso) + 4 rects (limbs) + swappable eyes/mouth, pure inline SVG, no image assets. Colors are hardcoded constants, never themed or re-tinted. Always animated (gentle float). Props: pose (nine values, below), size?: number (px, height auto-scales ×1.2), bare?: boolean. Prefer PageMascot over rendering Tak directly — it owns the standard size, the speech bubble and the mood→pose mapping. Reach for raw Tak only for the two bare icon call sites; the navbar logo uses the separate TakMark component instead (see below).

bare renders the badge treatment — body + eye rects only, no limbs, no mouth, no float — for use inside a control, where TAK is an icon rather than a character. The bug-report FAB and the landing streak ring are where this applies. Everywhere else uses the full mascot or TakMark.

Timing: resting float 2.6s / arm swing 1.8s. Each pose can override the whole-figure animation via anim and the limb swing via swingDur; the happier and sadder tiers run faster. Keyframes live in frontend/app/globals.css: tak-float, tak-bounce, tak-shake, tak-pulse, tak-wobble — mirroring Tak Mascot Standalone.html. sus is deliberately motionless.

Trap: Tak must not set inline display or flex-shrink — inline styles outrank utility classes, so a hidden sm:block sibling still renders and you get two mascots. Scale a single instance with w-*/h-* classes rather than rendering one per breakpoint.

TakChevron — the arrow mark

Back Next 10px inline mark, both directions

frontend/components/TakChevron.tsx. Reuses TAK's own torso polygon — the same shape Tak.tsx calls a "chevron-torso skeleton" — but cropped tight to just that polygon's bounding box (viewBox="55 70 93 90") instead of the full 200×240 character canvas, so it reads as a small arrow glyph rather than a mostly-empty icon at inline text sizes. Fill colour comes from BODY, exported from Tak.tsx so the two files share one color constant instead of duplicating the hex.

PropValue
size?: numberWidth in px, default 11. Height follows the polygon's aspect ratio (90/93).
direction?: 'right' | 'left'Default 'right'. 'left' mirrors via CSS transform: scaleX(-1) — one geometry, no second path.

Used for decorative navigational arrows only — trailing/leading →/← on links like "Study →" or "← Back to lists", and prev/next pagination buttons. Not used for dropdown/accordion carets, the small triangle expand/collapse glyphs, or the ⭐ difficulty-rating glyphs — see Emoji & arrow policy. /dashboard/admin/** is out of scope, same as PageMascot.

Inside an icon badge — size={16}: the logged-in home's "Продолжить занятие" CTA (app/LandingClient.tsx) puts the mark in the existing w-9 h-9 (36px) rounded-xl bg-emerald-500 badge, replacing a bespoke play-triangle SVG that existed nowhere else in the system. 16px, not the 22px the old triangle used: TakChevron is a solid filled polygon while that triangle was a 1.5px stroke, so matching its box would read far heavier. Note the fill is BODY (#ec3013), not currentColor — a text-color class on the badge does not tint it, and the orange-on-emerald pairing is intentional, the same TAK-accent exception the logo lockup uses.

StarLevelToggle — complexity selector

frontend/app/dashboard/components/StarLevelToggle.tsx. A three-stop pill (44×24, borderless, bg-[#f2f3f3] track) the user clicks to cycle complexity 1→2→3→1. Used on Слова and Фразы list rows.

The 18px knob is clipped with the same polygon as TakChevron, renormalized to percentages of its own box (clip-path: polygon(0% 0%, 64.5% 0%, 100% 50%, 64.5% 100%, 0% 100%, 35.5% 50%)), so it reads as TAK's chevron silhouette instead of a circle. It stays bg-ink, not TAK's red — TAK's red (#ec3013) is a brand constant reserved for TAK himself, so this borrows the shape motif only, never the colour.

Trap: the chevron's concave notch leaves only the right ~64.5% of the knob unclipped, and that band is too small to hold 2-3 ★ glyphs (or even a • glyph) legibly at 18px — both blur into each other or into the clip edge. The knob shows level count as small explicit 2.5px circle <span> elements instead of a text glyph. The fuller ★×level rendering is kept for the hover tooltip, where there's room for it.

PageMascot — the one reusable mascot

frontend/components/PageMascot.tsx. TAK plus a comic speech bubble, at the standard 128px. Exactly one per rendered screen, on every page except /dashboard/admin/**. Props: phrase: string (the page's own phrase, shown at neutral mood), mood?: number (−3…+3, default 0), size?, className?. Replaced TakGreeting, which no longer exists.

Mood lives in frontend/lib/mascotMood.ts (useMascotMood(), moodPose(), moodPhrase()). It is per study/practice session: neutral at the start, +1 per correct answer, −1 per wrong one (a timeout counts as wrong), clamped to ±3. Nothing is persisted — leaving the session or reloading returns TAK to neutral. Pages outside a session pass no mood and stay neutral. Wired into QuizSession.tsx, PhraseSession.tsx and app/dashboard/grammar/page.tsx; the done screens force at least +1 so a passed lesson never shows a sad TAK.

PageShell — the shared top-nav page shell

frontend/app/dashboard/components/PageShell.tsx. The outer wrapper for all 5 top-nav dashboard pages — Слова (/dashboard/lists), Фразы, Грамматика, Практика, Статьи. One <main className="min-h-screen text-gray-900"> + one <div className="page px-4 sm:px-8 pt-7">: the tested 1180px .page container, no decorative blur blob, no drop shadow. Historical origin — /dashboard/grammar and /dashboard/lists already used this before PageShell existed as a component; design-system-parity.spec.ts guarded it there first and now checks all 5 pages.

Фразы, Практика and Статьи were migrated onto it — they previously used an older generation of this shell (896px container, bg-[#F5F5F7], a decorative blur blob, and shadow-sm hover:shadow-md on cards). That generation is retired; do not reintroduce it on a new page.

Page order inside the shell — two sub-patterns, not one: Слова, Фразы and Практика put the hero ProgressStatCard above the title (card → banner → title+subtitle → content), guarded by tests/stats-card-alignment.spec.ts ("stats card is rendered above the page title"). Грамматика is the one exception — its beta-notice banner reads better directly under the title, so it keeps title+subtitle → banner → hero → content. Both are fine; what must not happen is a third ordering. Every page ends the same way: main content (accordion / grid) → "browse all" link (text-emerald-600 hover:text-emerald-700).

Mascot placement: lives inside the hero card's icon prop when a hero renders. On the states where a hero can't render yet — loading, or no enrolled content (Грамматика, Практика) — it falls back to beside the title, so exactly one mascot is always on screen. Статьи has no hero at all (no progress concept for reading), so its mascot always sits beside the title. This is not a settled bug: Фразы' hero is gated on a stats-fetch that rarely fails, so its title carries no such fallback — a known, accepted gap, not a pattern to copy for a page whose hero is normally absent.

Category tab bar (Статьи): frontend/app/dashboard/articles/ArticlesList.tsx — sits directly under the title/subtitle+mascot row and above the article card grid. Reuses the same visual recipe as the header's "Nav tab pills" (bg-[#f2f3f3] rounded-full p-1 gap-1 track; px-4 py-2 text-sm rounded-full items; active bg-white font-semibold text-ink shadow-[0_1px_2px_rgba(0,0,0,0.06)]; inactive text-muted) rather than inventing a new chip style. Driven by useSearchParams/router.push on ?category= (values: learning_materials | adaptation | blog, omitted = all); filters the already-fetched article list client-side, no extra request. Wrapped in <Suspense> since useSearchParams requires it under static export.

Session components — QuizSession / PhraseSession / GrammarTaskRunner

The three "answer things one at a time" screens are presentational components driven by props, so a page can compose them without duplicating their UI: app/dashboard/components/QuizSession.tsx (words), app/dashboard/components/PhraseSession.tsx (phrases) and app/dashboard/components/GrammarTaskRunner.tsx (grammar). Each owns its own card layout, mascot mood, progress bar and answer feedback; the caller owns loading the content and deciding what happens at the end.

GrammarTaskRunner is an extraction, not a new design. It was lifted verbatim out of app/dashboard/grammar/page.tsx, which used to inline the lesson list, the exercise screen and its own done screen in one 1000-line component with zero props. Only the exercise screen moved — the lesson list and grammar's own done screen (next-lesson / repeat / back-to-lessons) stayed on the page and are unchanged. It carries InlineSentenceInput, GrammarRuleCard and VerbHintCard with it (they had no other call sites) and renders all four task types (declension, sentence, verb_conjugation, verb_case). Props: tasks, level, rules?, hint?, onExit, onFinish(score, total, mood). It never fetches, never charges quota and never saves a result — the caller does, which is what lets both the standalone lesson and one phase of a combined session reuse it. mood is handed back so the caller's done screen can carry TAK's final mood over unchanged.

Multi-phase composition — onAdvance: QuizSession and PhraseSession take one optional prop. When onAdvance is set, this is a non-final phase of a multi-phase session: the match round's onDone calls it directly instead of setting done, so that phase's own "session complete" screen (mascot, stats tiles, pass/fail) never renders at all — the next phase's content simply replaces it. Only the true last phase in the sequence shows a done screen, with its normal unmodified behaviour. Omitting the prop leaves the component's original behaviour untouched, so existing callers are unaffected.

Deliberately not a relabeled button. An earlier version surfaced onAdvance as a relabeled primary button on the done screen ("Дальше — грамматика" instead of "Ещё раз"). Real usage showed that a full congratulatory stats screen between phases reads as the session having ended, even with a different button label — the fix was to skip that screen entirely for non-final phases, not to relabel it. There is no advanceLabel prop; don't reintroduce one without re-reading documentation/IMPLEMENTATION.md's account of this first.

The composed page: app/dashboard/continue/page.tsx ("Продолжить занятие") runs words → grammar → phrases back-to-back from a single GET /api/me/continue-session response — one request, because that is where the backend charges the daily quota exactly once for the whole flow. It holds a phaseIdx over the returned phases array and passes backHref="/" to every phase. A phase the backend omitted (nothing due) simply never renders — it is not an error state. Its loading / limit-reached / empty screens reuse the same markup as app/dashboard/review/page.tsx, and its strings live under tr.continueSession plus the existing tr.common.limitTitle/limitBody/tr.review.nothingTitle.

Enrollment gate. Before fetching anything, the endpoint checks the user has at least one enrollment in each of words/grammar/phrases; zero in any one blocks the whole session (hard gate, no partial session) and the page shows a dedicated screen (data-testid="continue-needs-enrollment", same card/button chrome as the other /dashboard/continue screens) linking out to that category's existing enroll page instead of building a picker inline. Its own settings — per-phase item counts and an "include new content" toggle — live on a fourth /dashboard/settings tab ("Комбо-тренировка"), styled identically to the existing "Слова"/"Фразы" tabs (same slider and card markup, own save button).

Emoji & arrow policy

TAK replaces decorative emoji (🎓📊📚🏆⭐🎉🔥) in stat icons, empty states, and celebration screens. It does not replace functional glyphs — lock icons, checkmarks, or the ⭐ difficulty-rating glyphs on word/phrase rows (those are data, not decoration).

The same split applies to arrows, via TakChevron: decorative navigational arrows — trailing/leading →/← on links ("Study →", "← Back to lists") and prev/next pagination — now render TAK's chevron mark. Small functional carets — dropdown/accordion expand-collapse triangles, the avatar-menu ▾ — stay plain glyphs; at ~12px a mascot-derived shape reads as illegible and makes the open/closed state ambiguous, so those were deliberately left alone. Admin-only UI (/dashboard/admin/** — e.g. the admin rewards tab label, admin practice back-links, admin pagination) was never in scope for either — this is a user-facing product decision, not an internal-tooling one.

Parity guard

frontend/tests/design-system-parity.spec.ts asserts the page wash, the brand green, the full-bleed navbar, the 1180px container, the segmented language pill, the ink wordmark with a green dot, that no other bare link is accidentally green, that the FAB renders exactly one bare mascot and hides its label on mobile, that the hamburger opens the nav, and that no text uses #d1d5db. The 1180px-container and no-blur-blob checks run across all 5 top-nav pages (Слова, Фразы, Грамматика, Практика, Статьи), not just Грамматика — this is the executable guard against exactly the drift that made those pages diverge in the first place. Run it after any change to shared shell or tokens, and add a new top-nav page's URL to the NAV_PAGES list in that spec when one is added.
