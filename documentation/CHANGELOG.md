| 4 | 2026-08-20 | Fix #158: the instrumental (Įnagininkas) rule card described only declensions I–III, while the exercise pool contains IV (*sūnus*, *profesorius*) and V (*sesuo*, *duktė*, *vanduo*) nouns. Because the learner types the **stem-relative** ending while the card was written in **nominative** terms, the card did not merely omit those forms — it actively mispredicted them (`-is/-ys→-iu` implies *profesoriu*, but the graded answer is *profesoriumi*). Added a new invariant — *every `answer_ending` reachable in a case's live sentences must be derivable from that case's rule card* — enforced by `backend/scripts/audit_case_rule_coverage.py` and the live-data half of `frontend/tests/issue-158-instrumental-iv-v-declension.spec.ts`. **Scope deliberately narrowed to the reported case (5):** the same I–III-only gap exists in cases 2, 3, 4, 6, 7, 8, 9 and 13 and is tracked as known debt via `GUARDED_CASES`/`DEFERRED_CASES` in both the script and the spec, with verified replacement strings kept in the plan file's Deferred section. See `documentation/grammar-sentence-data-integrity.md`. |
| 5 | 2026-08-20 | Review flow rework: maturity-aware stage graph + interleaved scheduling. A **mature** word (`status=known` and `sm2_reps >= MATURE_WORD_REPS`, decided server-side and sent as `mature`) now opens on the typing card with no answer-revealing flashcard; a miss or the new «Забыл» button drops it into the full learning flow (CARD → SELECT → ASSEMBLE → TYPE). «Легко» → type, and a typing miss demotes to the difficult path (SELECT → ASSEMBLE → TYPE) — which now runs for **every** entry type, because `buildAssemblyTiles` (`frontend/lib/assembleTiles.ts`) picks whole-word, syllable or letter tiles instead of `isSingleWordEntry` skipping phrases, multi-form entries and one-syllable words entirely. A mistake anywhere in a chain costs 2× assemble + 2× type, once per word per session (1× + 1× in quick mode). Cards are no longer spliced in as a contiguous block: `scheduleCards` (`frontend/lib/scheduleCards.ts`) interleaves them so no two cards of one word sit next to each other and no three consecutive cards share an exercise bucket — the `'3s'` near-miss drill is the one deliberate exception, keeping its near-the-front placement. Two words with an identical translation can no longer meet: `_dedupe_by_translation` runs in all six session-building endpoints with a `limit × 3` over-fetch so a dropped twin is backfilled, `pickDistractors`/`buildOptions2r` also de-duplicate on the *displayed* translation, and the collision key deliberately **keeps** parentheses so issue #152's qualifiers stay distinguishable. Audit: `backend/scripts/audit_duplicate_translations.py` (52 ru groups / 133 words, 20 same-list). See `documentation/review-flow-stage-graph.md`. |
