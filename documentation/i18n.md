# UI language (RU / EN)

The UI language is `lang` from `frontend/lib/useT.ts` (`tr`, `plural`, `lang`) over
`frontend/lib/i18n/{types,ru,en}.ts`. Every user-visible string lives in those dictionaries.
Dates and numbers take their locale from `tr.common.dateLocale`, never a hardcoded `'ru-RU'`.

## The guard: `frontend/tests/no-hardcoded-russian.spec.ts` (#48a)

This is a static source check, not a browser test. It reads every `.ts`/`.tsx` under `app`,
`components` and `lib`, strips comments, and fails on Cyrillic or a `'ru-RU'` literal, listing
`file:line`. It does not check:

- `lib/i18n/ru.ts`
- `metadata` / `generateMetadata` blocks, because RU SEO titles are deliberately Russian (see
  `seo.md`)
- lines marked `// i18n-allow: <reason>`

**Why static instead of Playwright across screens:** we chose this during the #48 plan review.
Rendering ~25 mocked screens only proves the UI against fixtures the same agent writes, covers only
the states someone remembered to mock, and is slow and flaky. The source check runs in
milliseconds and covers every file, including screens nobody listed. A small EN render smoke
(`tests/en-smoke.spec.ts`) covers what source can't see: plural and locale wiring.

## When `// i18n-allow` is right

Only for text that is *content in a fixed language*, not UI copy:
- lookup tables keyed by RU DB values (`lib/wordHint.ts`)
- sample placeholders inside a field whose content language is Russian (the program editor's RU
  title/translation inputs)

Labels, buttons and notes always go through `tr`, even on bilingual forms.

## Gotcha: `useState` initializers run while `lang` is still `'ru'`

`useLang` starts at `'ru'` and switches to the stored language in an effect. A `useState(...)`
initial value or a `useCallback(..., [])` that reads `tr` freezes the RU string. Example: the
program editor's default «Набор 1». Keep translated defaults out of state: render them at display
time, or use them as a placeholder.

## DB content

Admin-authored content uses paired `_ru` / `_en` columns, and the frontend picks
`lang === 'en' ? (x_en ?? x_ru) : x_ru`. Values stored in the DB in Russian with a fixed vocabulary
(`word.hint`, the default set title «Набор N») are mapped at display time in `lib/wordHint.ts`.
The DB rows aren't rewritten.
