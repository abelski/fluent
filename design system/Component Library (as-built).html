What's actually implemented in frontend/ after the TAK mascot redesign, kept in sync with the code. The original mockups (Fluent Redesign - Design System.html, prototypes/) are the design intent this was built from — this page documents what shipped, including the places implementation deliberately diverged (mobile sizing, a11y, existing i18n/data constraints).

Per CLAUDE.md: update this file whenever a new shared component or pattern is introduced. This is the source of truth for visual/component decisions during development — check it before inventing a new pattern.

Principles

  1. The prototypes are the visual source of truth. prototypes/*.html define layout, spacing and colour. This page records what shipped. When they disagree, the prototype wins unless the divergence is listed under "Deliberate deviations" below.
  2. Flat, not decorated. Cards are white with a 1px #ececec border and no drop shadow. Buttons carry no shadow or glow. No decorative blur blobs, no gradient fills on components — the only gradient in the product is the page wash on body.
  3. Tokens, not raw palette steps. Use the named colours above. Never reach for a stock Tailwind step (gray-100, emerald-500) when a token exists — that drift is what made the app diverge from the mockups in the first place.
  4. One typeface. Inter everywhere. The prototypes use no second display face, so font-headline (Manrope) is not applied on redesigned pages.
  5. Green is words, purple is phrases. #0f9d68 is the words/global accent; #9333ea is the phrases surface. Correct/incorrect feedback stays green/red regardless of surface — that is semantic, not brand.
  6. Hover goes darker, never lighter. emerald-600 → emerald-700.
  7. Layout: full-bleed navbar, 1180px content. The header spans the viewport; page content sits in .page (max 1180px, 32px gutters, 16px below 860px).
  8. Breakpoints follow the prototypes, not Tailwind defaults: 3→2 columns at 1000px, →1 column at 860px.
  9. Readability outranks fidelity. If a prototype value is genuinely hard to read, darken it and record it as a deliberate deviation. Small-caps secondary labels use #5b6067.
  10. TAK is the only mascot, and replaces decorative emoji — never functional glyphs. See Emoji policy.

TAK — the mascot

frontend/components/Tak.tsx. One polygon (torso) + 4 rects (limbs) + swappable eyes/mouth, pure inline SVG, no image assets. Colors are hardcoded constants, never themed or re-tinted. Always animated (gentle float). Props: pose: 'idle' | 'stonks' | 'grin' | 'talking', size?: number (px, height auto-scales ×1.2), bare?: boolean.

bare renders the badge treatment — body + eye rects only, no limbs, no mouth, no float — for use inside a control, where TAK is an icon rather than a character. The bug-report FAB is the one place this applies; the prototypes draw it exactly this way. Everywhere else uses the full mascot.

Timing: resting float 2.6s / arm swing 1.8s. The grin pose speeds up for celebration — 2s / 0.7s — via floatDur/swingDur on the pose spec.

Trap: Tak must not set inline display or flex-shrink — inline styles outrank utility classes, so a hidden sm:block sibling still renders and you get two mascots. Scale a single instance with w-*/h-* classes rather than rendering one per breakpoint.

idle Default. Hero-card icon, FAB, empty states.
talking TakGreeting companion. Prompts, speech-bubble pairing.
stonks Confident squint, raised arm. Progress/streak moments.
grin Big grin. Celebration/completion — trophy & done screens.

Emoji policy

TAK replaces decorative emoji (🎓📊📚🏆⭐🎉🔥) in stat icons, empty states, and celebration screens. It does not replace functional glyphs — lock icons, checkmarks, chevrons, or the ⭐ difficulty-rating glyphs on word/phrase rows (those are data, not decoration). Admin-only UI (e.g. the admin rewards tab label) was never in scope — this is a user-facing product decision, not an internal-tooling one.

Deliberate deviations from the prototypes

DeviationWhy
Mobile hamburger menu keptThe prototypes have no hamburger, but they were only ever drawn at desktop width — their silence isn't a decision about mobile.
FAB label hidden below smPrototype keeps it at 13px; hiding it protects the tap target on narrow screens, leaving a round icon button.
Small-caps secondary labels at #5b6067Prototypes use #b0b4ba and the app had drifted lighter still to #d1d5db. Both were reported unreadable; #5b6067 clears WCAG AA at these sizes.

Parity guard

frontend/tests/design-system-parity.spec.ts asserts the page wash, the brand green, the full-bleed navbar, the 1180px container, the segmented language pill, the ink wordmark with a green dot, that no other bare link is accidentally green, that the FAB renders exactly one bare mascot and hides its label on mobile, that the hamburger opens the nav, and that no text uses #d1d5db. Run it after any change to shared shell or tokens.
